現行Function実装との差分
現時点では、以下が目標仕様と一致していません。
1. Conditionalが未実装
Retention、Function Procedureともに、If／Then／Elseによるノード制御はありません。
2. Returnが「1つ・Procedure末尾固定」
現行ランタイムは次を要求しています。
- Returnは必ず1つ
- Procedure直下
- Procedure末尾
目標仕様では次になります。
- 非Void：全正常終了経路でReturn
- 複数のReturnを許可
- Conditional分岐内のReturnを許可
- Void：Returnなしを許可
- Voidでも早期Returnを許可
3. Void FunctionでもReturn必須
現行ランタイムはVoidを含め、Returnがないとエラーになります。目標仕様ではVoid Returnは任意です。
4. Return式が必須プロパティ
現在は次の形式です。
source: string
Voidも空文字で表現しています。先ほど合意した目標は次です。
source?: string
Void Returnではsourceプロパティ自体を持ちません。
5. Function作成時にReturnを生成しない
現在はArgumentsとProcedureだけを自動生成し、Returnはメニューから手動追加します。
以前合意した「非Void Function作成時には初期値式を持つReturnを生成する」は未実装です。ただしConditional導入後は、Returnの配置方法と合わせて再設計する必要があります。
6. ReturnをConditional配下へ置けない
現在のReturnはProcedure直下だけに制限されています。将来はConditionalのThen／Else配下へ配置できる必要があります。
7. Function呼び出しごとに構造を走査している
現在はFunction実行時に毎回、以下を検査しています。
- Arguments／Procedureの数
- Procedure内の許可要素
- Returnの数と位置
- Return式の有無
これは直近の安全対策として追加したものですが、最終方針の「重い要素依存チェックはApp起動前」に対して過剰です。App Validator完成後は、ランタイム側を軽量Assertへ縮小する必要があります。
8. App／Project Validatorが未実装
現在は以下がありません。
- system/validationフォルダ
- App起動前検証
- App手動チェック
- Project手動チェック
- 検証結果一覧とノード移動UI
- 検証結果キャッシュ
9. ランタイム専用エラー画面が未実装
Function実行エラーは現在のスクリプトエラーとして伝播しますが、App全体を安全に停止する中央エラー境界や専用画面はありません。
10. 既存Function仕様書が古い
[FUNCTION_ELEMENT_SPEC.md](C:/app/git/mebaco/docs/FUNCTION_ELEMENT_SPEC.md)には、現在の方針と異なる以下の記述が残っています。
- Function保存時にReturnを検証
- Returnは最大1つ
- Procedure末尾固定
- VoidでもReturn必須
今回はご指定どおり検証資料だけを追加し、このFunction仕様書は変更していません。ConditionalとReturnの最終仕様が固まった段階で、別途更新が必要です。
なお、Save時に検証しない現在の動作は、目標方針と一致しています。
