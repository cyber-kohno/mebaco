# Mebaco 命名経緯

## 1. 背景

新しい Front Driven は、ローカルで動作する開発・実行の統合基盤として構想している。

ツリー構造で UI や Component を組み、TypeScript によって振る舞いを記述し、その場で実行できる「フロントエンド版 Unity」のような体験を目指す。

## 2. 初期の命名方針

当初は、この特徴を直接表す名前として、`UI`、`Front`、`Tree`、`Node` などを含む造語を検討した。

`Uinova` や `Vistree` などは語感もよく方向性に合っていたが、既存サービスとの重複が見つかった。

開発ツール名として検索性・識別性を確保するには、機能語を直接組み合わせる名前は競合しやすいと判断した。

## 3. 比喩による再検討

そこで、製品の概念を直接説明するのではなく、象徴的な比喩で表現する方向へ切り替えた。

候補として、天文台、星図、舞台、織機、結晶、庭、温室などを検討した。

その中でも特に、今後の差別化要素として「独自の部品を育て、配置し、再利用していく体験」を重視したいという理由から、**庭 / 温室** の比喩を中心に据えることにした。

この比喩では、Project は庭、Component は苗や株、Runtime は温室、再利用は挿し木や株分けのように捉えられる。

単なるローコード開発環境ではなく、使うほどに自分の部品資産が育っていくローカルな制作環境、という製品思想と相性が良い。

## 4. Mebaco という名前

その流れで、可愛く親しみやすいが、既存サービスと致命的に被りにくい名前として **Mebaco / メバコ** が候補に残った。

`Mebaco` は「芽箱」と解釈でき、部品の芽を育てて収める小さな箱、という意味づけができる。

また、ローカル環境を「箱」として表現する方向性とも合っている。

`Mebaco` には、開発ツールとしては少し可愛すぎるのではないか、チープに見えないかという懸念もあった。

しかし、名前自体は親しみやすくても、UI、ロゴ、サブコピー、ドキュメントのトーンを落ち着いたものにすれば、開発ツールとしての信頼感は十分に出せると判断した。

むしろ、硬すぎない名前は記憶に残りやすく、製品の独自性にもつながる。

## 5. 決定

短く、覚えやすく、語感がよく、検索上の致命的な重複も少なく、将来的な展開にも向いているため、新アプリ名は **Mebaco** とする。

将来的な派生名としても、以下のように展開しやすい。

```text
Mebaco
Mebaco CLI
Mebaco Runtime
Mebaco Desktop
Mebaco Boutique
Mebaco Project
```

ブランドの中心コンセプトは次のように整理できる。

```text
Mebaco = 芽箱。
アプリの部品を育て、保存し、再利用するためのローカルな箱。
```

製品説明としては、以下のような方向性が合う。

```text
Mebaco
部品を育てる、ローカルアプリ開発の箱。

Mebaco
育てて使う、フロントエンド開発環境。

Mebaco
A local studio for growing app components.
```
